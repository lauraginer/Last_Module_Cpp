1. EXCEPCIONES EN C++
================================================================================

Las excepciones en C++ son un mecanismo para manejar errores o situaciones 
inesperadas (como división por cero o falta de memoria) que ocurren durante la 
ejecución de un programa, evitando su cierre inesperado. Permiten separar la 
lógica de error del flujo normal del código mediante bloques try, catch y throw,
facilitando la creación de programas robustos y ordenados.

1.1 COMPONENTES CLAVE DEL MANEJO DE EXCEPCIONES
--------------------------------------------------------------------------------

• throw (Lanzar): 
  Cuando ocurre un error, se "lanza" una excepción utilizando la palabra clave 
  throw. La excepción puede ser de cualquier tipo (int, string, clase, etc.), 
  aunque generalmente se usan clases derivadas de std::exception.
  
  Sintaxis: throw valor_o_objeto;

• try (Intentar): 
  Envuelve un bloque de código que podría lanzar una excepción. El código dentro
  del bloque try se ejecuta normalmente hasta que se lance una excepción.
  
  Sintaxis: try { /* código que puede lanzar excepciones */ }

• catch (Capturar): 
  Sigue al bloque try y contiene el código para manejar la excepción específica.
  Puede haber múltiples bloques catch para diferentes tipos de excepciones.
  
  Sintaxis: catch (TipoExcepcion& e) { /* manejo de la excepción */ }


1.2 FLUJO DE EJECUCIÓN CON EXCEPCIONES
--------------------------------------------------------------------------------

1. El código se ejecuta normalmente dentro del bloque try
2. Si se lanza una excepción (throw), la ejecución del bloque try se detiene
3. El programa busca un bloque catch que coincida con el tipo de excepción
4. Si se encuentra, se ejecuta el código del catch correspondiente
5. La ejecución continúa después de todos los bloques catch
6. Si NO se encuentra un catch apropiado, el programa termina


1.3 EJEMPLO BÁSICO DE EXCEPCIONES
--------------------------------------------------------------------------------

#include <iostream>
#include <stdexcept>

int dividir(int numerador, int denominador) {
    if (denominador == 0) {
        throw std::runtime_error("Error: División por cero");
    }
    return numerador / denominador;
}

int main() {
    try {
        std::cout << "Resultado: " << dividir(10, 2) << std::endl;  // OK
        std::cout << "Resultado: " << dividir(10, 0) << std::endl;  // Lanza excepción
        std::cout << "Esta línea nunca se ejecutará" << std::endl;
    }
    catch (const std::runtime_error& e) {
        std::cout << "Excepción capturada: " << e.what() << std::endl;
    }
    std::cout << "El programa continúa después del catch" << std::endl;
    return 0;
}

/* SALIDA:
Resultado: 5
Excepción capturada: Error: División por cero
El programa continúa después del catch
*/


1.4 MÚLTIPLES BLOQUES CATCH
--------------------------------------------------------------------------------

Se pueden usar varios bloques catch para capturar diferentes tipos de excepciones:

#include <iostream>
#include <stdexcept>
#include <string>

void procesamientoComplejo(int opcion) {
    if (opcion == 1)
        throw std::runtime_error("Error de ejecución");
    else if (opcion == 2)
        throw std::out_of_range("Fuera de rango");
    else if (opcion == 3)
        throw 42;  // Lanzar un entero
    else if (opcion == 4)
        throw std::string("Error de tipo string");
}

int main() {
    for (int i = 1; i <= 5; i++) {
        try {
            std::cout << "\nPrueba " << i << ": ";
            procesamientoComplejo(i);
            std::cout << "Sin excepciones" << std::endl;
        }
        catch (const std::runtime_error& e) {
            std::cout << "runtime_error: " << e.what() << std::endl;
        }
        catch (const std::out_of_range& e) {
            std::cout << "out_of_range: " << e.what() << std::endl;
        }
        catch (int num) {
            std::cout << "Excepción int: " << num << std::endl;
        }
        catch (const std::string& str) {
            std::cout << "Excepción string: " << str << std::endl;
        }
        catch (...) {  // Captura CUALQUIER excepción
            std::cout << "Excepción desconocida" << std::endl;
        }
    }
    return 0;
}

/* SALIDA:
Prueba 1: runtime_error: Error de ejecución
Prueba 2: out_of_range: Fuera de rango
Prueba 3: Excepción int: 42
Prueba 4: Excepción string: Error de tipo string
Prueba 5: Sin excepciones
*/


1.5 RELANZAR EXCEPCIONES
--------------------------------------------------------------------------------

Puedes capturar una excepción, hacer algo, y luego relanzarla con throw;

#include <iostream>
#include <stdexcept>

void funcionInterna() {
    throw std::runtime_error("Error en función interna");
}

void funcionIntermedia() {
    try {
        funcionInterna();
    }
    catch (const std::exception& e) {
        std::cout << "Capturada en intermedia: " << e.what() << std::endl;
        throw;  // Relanza la misma excepción
    }
}

int main() {
    try {
        funcionIntermedia();
    }
    catch (const std::exception& e) {
        std::cout << "Capturada en main: " << e.what() << std::endl;
    }
    return 0;
}

/* SALIDA:
Capturada en intermedia: Error en función interna
Capturada en main: Error en función interna
*/

2. CLASES ANIDADAS (NESTED CLASSES)
================================================================================

Las clases anidadas son clases definidas dentro de otra clase. Son útiles para:
• Organizar código relacionado
• Crear excepciones personalizadas específicas de una clase
• Limitar el alcance de una clase auxiliar
• Ocultar detalles de implementación


2.1 SINTAXIS BÁSICA DE CLASES ANIDADAS
--------------------------------------------------------------------------------

class ClaseExterna {
public:
    class ClaseInterna {
        // Miembros de la clase interna
    };
    
private:
    class ClasePrivadaInterna {
        // Solo accesible dentro de ClaseExterna
    };
};

// Uso desde fuera:
ClaseExterna::ClaseInterna obj;  // OK si es pública
// ClaseExterna::ClasePrivadaInterna obj2;  // ERROR: es privada


2.2 EXCEPCIONES PERSONALIZADAS CON CLASES ANIDADAS
--------------------------------------------------------------------------------

Esta es la forma más común de usar clases anidadas en los ejercicios de C++:

#include <iostream>
#include <exception>

class Bureaucrat {
private:
    std::string _name;
    int _grade;
    
public:
    // Constructor
    Bureaucrat(std::string name, int grade) : _name(name), _grade(grade) {
        if (grade < 1)
            throw GradeTooHighException();
        if (grade > 150)
            throw GradeTooLowException();
    }
    
    // Getters
    std::string getName() const { return _name; }
    int getGrade() const { return _grade; }
    
    // Métodos que pueden lanzar excepciones
    void incrementGrade() {
        if (_grade <= 1)
            throw GradeTooHighException();
        _grade--;
    }
    
    void decrementGrade() {
        if (_grade >= 150)
            throw GradeTooLowException();
        _grade++;
    }
    
    // CLASES ANIDADAS: Excepciones personalizadas
    class GradeTooHighException : public std::exception {
    public:
        virtual const char* what() const throw() {
            return "Grade is too high! (minimum is 1)";
        }
    };
    
    class GradeTooLowException : public std::exception {
    public:
        virtual const char* what() const throw() {
            return "Grade is too low! (maximum is 150)";
        }
    };
};

// Sobrecarga del operador <<
std::ostream& operator<<(std::ostream& out, const Bureaucrat& b) {
    out << b.getName() << ", bureaucrat grade " << b.getGrade();
    return out;
}

int main() {
    // Caso 1: Creación exitosa
    try {
        Bureaucrat bob("Bob", 50);
        std::cout << bob << std::endl;
    }
    catch (const std::exception& e) {
        std::cout << "Error: " << e.what() << std::endl;
    }
    
    // Caso 2: Grade demasiado alto al crear
    try {
        Bureaucrat alice("Alice", 0);  // Lanza GradeTooHighException
        std::cout << alice << std::endl;
    }
    catch (const std::exception& e) {
        std::cout << "Error: " << e.what() << std::endl;
    }
    
    // Caso 3: Grade demasiado bajo al crear
    try {
        Bureaucrat charlie("Charlie", 151);  // Lanza GradeTooLowException
        std::cout << charlie << std::endl;
    }
    catch (const std::exception& e) {
        std::cout << "Error: " << e.what() << std::endl;
    }
    
    // Caso 4: Incrementar demasiado
    try {
        Bureaucrat dave("Dave", 1);
        std::cout << dave << std::endl;
        dave.incrementGrade();  // Lanza GradeTooHighException
    }
    catch (const std::exception& e) {
        std::cout << "Error incrementando: " << e.what() << std::endl;
    }
    
    // Caso 5: Decrementar demasiado
    try {
        Bureaucrat eve("Eve", 150);
        std::cout << eve << std::endl;
        eve.decrementGrade();  // Lanza GradeTooLowException
    }
    catch (const std::exception& e) {
        std::cout << "Error decrementando: " << e.what() << std::endl;
    }
    
    // Caso 6: Operaciones exitosas
    try {
        Bureaucrat frank("Frank", 75);
        std::cout << frank << std::endl;
        
        frank.incrementGrade();  // 75 -> 74
        std::cout << "Después de incrementar: " << frank << std::endl;
        
        frank.decrementGrade();  // 74 -> 75
        std::cout << "Después de decrementar: " << frank << std::endl;
    }
    catch (const std::exception& e) {
        std::cout << "Error: " << e.what() << std::endl;
    }
    
    return 0;
}

/* SALIDA:
Bob, bureaucrat grade 50
Error: Grade is too high! (minimum is 1)
Error: Grade is too low! (maximum is 150)
Dave, bureaucrat grade 1
Error incrementando: Grade is too high! (minimum is 1)
Eve, bureaucrat grade 150
Error decrementando: Grade is too low! (maximum is 150)
Frank, bureaucrat grade 75
Después de incrementar: Frank, bureaucrat grade 74
Después de decrementar: Frank, bureaucrat grade 75
*/


2.3 VENTAJAS DE LAS CLASES ANIDADAS PARA EXCEPCIONES
--------------------------------------------------------------------------------

1. Organización: Las excepciones están directamente relacionadas con la clase
2. Namespace: Se accede como Bureaucrat::GradeTooHighException, evitando 
   conflictos de nombres
3. Encapsulación: Las excepciones son parte lógica de la clase
4. Claridad: Es evidente qué clase puede lanzar qué excepciones


2.4 HERENCIA DE std::exception
--------------------------------------------------------------------------------

Es una buena práctica heredar de std::exception porque:

class MiExcepcion : public std::exception {
public:
    virtual const char* what() const throw() {
        return "Descripción del error";
    }
};

• what() devuelve un mensaje descriptivo del error
• throw() especifica que what() no lanza excepciones (obsoleto en C++11+)
• Permite capturar con catch (const std::exception& e) genérico
• Compatible con la jerarquía estándar de excepciones de C++


2.5 EJEMPLO COMPLETO CON MÚLTIPLES EXCEPCIONES
--------------------------------------------------------------------------------

#include <iostream>
#include <exception>
#include <string>

class BankAccount {
private:
    std::string _owner;
    double _balance;
    
public:
    BankAccount(std::string owner, double initialBalance) 
        : _owner(owner), _balance(initialBalance) {
        if (initialBalance < 0)
            throw InvalidAmountException();
    }
    
    void deposit(double amount) {
        if (amount <= 0)
            throw InvalidAmountException();
        _balance += amount;
    }
    
    void withdraw(double amount) {
        if (amount <= 0)
            throw InvalidAmountException();
        if (amount > _balance)
            throw InsufficientFundsException();
        _balance -= amount;
    }
    
    double getBalance() const { return _balance; }
    std::string getOwner() const { return _owner; }
    
    // Excepciones personalizadas como clases anidadas
    class InvalidAmountException : public std::exception {
    public:
        virtual const char* what() const throw() {
            return "Invalid amount: must be positive";
        }
    };
    
    class InsufficientFundsException : public std::exception {
    public:
        virtual const char* what() const throw() {
            return "Insufficient funds for this operation";
        }
    };
};

int main() {
    try {
        BankAccount account("John Doe", 1000.0);
        std::cout << "Balance inicial: $" << account.getBalance() << std::endl;
        
        account.deposit(500.0);
        std::cout << "Después de depositar $500: $" << account.getBalance() << std::endl;
        
        account.withdraw(300.0);
        std::cout << "Después de retirar $300: $" << account.getBalance() << std::endl;
        
        // Esto lanzará InsufficientFundsException
        account.withdraw(2000.0);
    }
    catch (const BankAccount::InsufficientFundsException& e) {
        std::cout << "Error de fondos: " << e.what() << std::endl;
    }
    catch (const BankAccount::InvalidAmountException& e) {
        std::cout << "Error de cantidad: " << e.what() << std::endl;
    }
    catch (const std::exception& e) {
        std::cout << "Error general: " << e.what() << std::endl;
    }
    
    // Intentar cantidad inválida
    try {
        BankAccount account2("Jane Doe", 500.0);
        account2.deposit(-100.0);  // Lanza InvalidAmountException
    }
    catch (const std::exception& e) {
        std::cout << "Error: " << e.what() << std::endl;
    }
    
    return 0;
}

/* SALIDA:
Balance inicial: $1000
Después de depositar $500: $1500
Después de retirar $300: $1200
Error de fondos: Insufficient funds for this operation
Error: Invalid amount: must be positive
*/

3. RESUMEN Y BUENAS PRÁCTICAS
================================================================================

TRY-CATCH-THROW:
• Usa try para código que puede fallar
• Usa throw para lanzar excepciones cuando detectes errores
• Usa catch para manejar las excepciones de forma específica
• Ordena los catch de más específico a más genérico
• Usa catch(...) como último recurso para capturar todo

CLASES ANIDADAS:
• Define excepciones como clases anidadas públicas
• Hereda de std::exception
• Implementa el método what() para mensajes descriptivos
• Usa el nombre de la clase externa para acceder: Clase::Excepcion

EXCEPCIONES EN CONSTRUCTORES:
• Los constructores pueden lanzar excepciones (no devuelven valores)
• Es la forma correcta de indicar que la construcción falló
• El objeto no se crea si el constructor lanza una excepción

EXCEPCIONES EN DESTRUCTORES:
• NUNCA lances excepciones en destructores
• Pueden causar terminación del programa
• Usa try-catch dentro del destructor si es necesario
